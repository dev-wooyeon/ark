## 이 주문 어디서 죽었어요? 배민주문 Temporal 전환기

**내용 요약**

- 주문이 멈춘 지점을 찾으려면 주문팀, 중개시스템팀, 접수채널팀의 로그를 대조해야 했어요. 여러 소비처가 있는 이벤트를 다시 발행할 때는 이미 처리한 곳에 미칠 영향도 고려해야 했고요.
- 주문의 진행 상태와 이력을 한곳에서 관리하기 위해 Temporal을 도입했어요. 직접 오케스트레이터를 만들 때 필요한 워커 장애 대응, 재시도, 취소, 보상, 동시성 제어도 선택의 배경이었어요.
- 도입 뒤에도 DB I/O와 클러스터 구성, 실패 복구를 운영에 맞게 설계했어요. 특히 실패 원인이 해소됐을 때 주문 전체가 아닌 필요한 단계만 골라 재시도할 수 있도록 만들었어요.
- 코드에서 진행 순서를 읽을 수 있도록, 외부 신호인 Signal은 상태 머신을 거쳐 상태를 바꾸고 실제 흐름은 Workflow 본문에서 다루도록 나눴어요.

**느낀 점**

저도 레이스와 액티비티의 흐름을 설계하고 있어서, 실패한 뒤 어디서부터 다시 처리할 수 있는지에 관심이 갔어요. 각 단계가 끝난 지점을 남기고 필요한 단계만 다시 실행할 수 있게 한 방식이 제 고민과 맞닿아 있었어요.

실패 원인이 사라졌다고 해서 전체를 처음부터 실행할 수는 없잖아요. 어디까지 자동으로 재시도하고 언제 사람이 개입할지, 이미 끝난 작업은 어떻게 다룰지 같은 질문이 남았어요. 제 설계에서도 정상적인 실행 순서와 함께 실패한 뒤 이어갈 경로를 그려보려고 해요.

- 폼의 입력 항목과 규칙을 JSON으로 구조화하고 기존 검증 규칙과 서버 API를 활용했어요. AI는 의도를 모으고 빠진 값을 되물으며 실행 전 확인을 받고, 스크립트는 입력 검증과 API 호출, 저장 결과 대조를 맡았어요.
- 쿠폰 이름에는 15% 할인이라고 적었지만 실제 할인율은 10%로 설정한 사례도 있었어요. 각각의 입력 조건은 통과해도 내용은 어긋날 수 있는데, AI가 두 값을 함께 읽고 이를 짚어줬어요.

화면을 고치는 대신 기존 폼 규칙을 대화에서도 활용할 수 있게 한 발상이 인상적이었어요. 왜 헤드리스 어드민이 필요했는지 듣고 시연까지 보니, 익숙한 기능도 입력받는 방식을 바꾸면 다르게 활용할 수 있겠더라고요.

- 지점별 상품 데이터는 본사와 다른 값만 따로 관리했어요. 지점 가격이 없으면 본사 가격을 따르므로 저장할 데이터는 줄지만, 읽을 때 적용할 값을 판단해야 해요.
- 재고는 외부 셀러의 원장을 플랫폼이 모두 소유할 수 없어서 원천을 유지하고 조회를 통합하는 전시 재고 시스템을 선택했어요. 저는 화면의 빠른 조회와 주문 시의 정확한 재고 확인이라는 요구 차이도 함께 고려한 선택으로 이해했어요.

**느낀 점**

이 세션에서 가장 기억에 남은 말은 “정말 같은가요, 닮았을 뿐인가요?”였어요.

저도 액티비티의 흐름을 설계하면서 비슷한 고민을 했어요. 처음에는 레이스도 다른 액티비티와 함께 하나의 모델로 다루려고 했어요. 멀리서 보면 모두 고객 탑승과 체크인, 게임 시작, 진행, 종료, 기록이라는 흐름으로 보였거든요.

그런데 레이스의 각 단계를 구체적으로 설계하니 다뤄야 할 것이 많았어요. 티켓 종류에 따른 동작과 시작 신호 제어, 정확한 기록을 위한 센서 시간값이 필요했어요. 구간별 데이터와 GPS, 실시간 데이터, 레이스 심사까지 들어가니 같은 이름의 단계 안에서도 처리해야 할 일이 달라졌어요.

결국 같은 프로젝트 안에서 운영하되, 레이스는 다른 액티비티와 의도적으로 분리했어요. 그 질문을 듣자 그때의 설계 과정이 떠올랐어요. 체크인과 시작, 종료라는 단계가 닮았다는 이유만으로 그 안의 요구사항까지 같다고 볼 수는 없었던 거죠.

상품은 함께 다루고 재고는 경계를 남긴 이유를 들으며, 레이스를 분리할 때 저도 비슷한 질문을 했다는 걸 알았어요. 다음에 액티비티를 설계할 때도 단계의 이름뿐 아니라, 그 안에서 처리해야 할 제어와 데이터를 함께 놓고 공통으로 다룰 범위를 정하려고 해요.

다른 팀의 의사결정 과정이 궁금해서 갔는데, 제가 하던 고민과 겹치는 질문이 많았어요. 작업이 실패한 뒤에는 어떻게 이어갈지, 비슷해 보이는 개념을 어디까지 함께 다룰지 같은 질문들이요.

경험과 시행착오를 나눠주신 분들께 감사해요. 저도 레이스와 액티비티를 설계하면서 막힐 때, 이번에 들은 질문들을 다시 꺼내볼 것 같아요.
